Build notes

Samsung Galaxy A8 2018 · LineageOS 24, Android 17, unofficial

Working on the phone

  • Updates install from the phone itself, and keep the Google apps
  • Camera, photos and video
  • Satellite positioning, about 37 seconds from cold at a window
  • Fingerprint reader
  • Bluetooth, calls, text messages, tap to pay
  • Temperature monitoring

Not working

  • Microphone. A hardware fault, proven by the second microphone starting instantly through the identical path. Not fixable in software.
  • Calls over 4G. Never set up on this port, a large job, left alone for now.

v37release

Newest

21 November 2026 · 1.07 GB

What changed

  • The Updates app can look for a new build online again. On the previous build a device setting held it to installing a file you pick by hand, so the Check for updates button was missing, and that could not be undone on a phone already running it.
  • Installing an update from a file no longer stops when the screen turns off. Before, the screen going dark cancelled the copy part way through and deleted the half-copied file.

What was checked

  • Both parts of the Updates app in the signed package carry the corrected setting. The check reads the value built into the app rather than looking for its name, and it was tried first against the previous build, which it correctly rejects.
  • All seventeen package checks passed, on the unsigned package and again on the signed one. The whole-package signature verified, the update certificate matches the one the recovery trusts, and both trust lists hold only the owner certificate.
  • The new files were compared against the previous build: of 8,048 files that held content before, not one is empty now.

Worth knowing

  • Not yet installed on a phone, so first boot is unverified.
  • The screen-off correction takes code away rather than adding any, so no package check can prove it. It needs a real install from a file with the screen left to go dark.
  • Looking for updates online has never been exercised on a build of this kind, because the previous one could not offer the button. The checks prove the button is no longer held back, not that the connection to the download page works.

v33debug

17 November 2026 · 1.08 GB

What changed

  • Double tap to wake now has a real switch: Settings, Display, Tap to wake. The last build carried the feature but there was no working way to turn it on.

What was checked

  • Nothing on the phone yet. This build had not been installed when these notes were written.

Worth knowing

  • Double tap to wake is unproven. Two things are unknown: whether the whole screen responds or only part of it, and whether the screen has to go off twice before it starts working. Both are being measured.
  • Leaving double tap to wake on keeps the touch screen listening while the screen is off, so it may cost battery. Not measured yet.
  • The Recent changes button still opens this page in a browser. A version that shows it inside the app is written but did not make this build.

v32debug

17 November 2026 · 1.08 GB

What changed

  • The Wi-Fi IPv6 setting now works. The previous build's attempt was undone by Android a moment after it was applied, as the phone finished joining a network. The part of the system that has the last word now holds the setting instead.
  • A charging limit, so the battery can be kept short of full. Settings, Battery.

What was checked

  • Updating from the phone itself, the whole way through. That is what this build was for, and it worked.
  • The Wi-Fi IPv6 setting was confirmed to hold through leaving a network and rejoining it, which is exactly where the previous attempt failed.

Worth knowing

  • The charging limit was not tested on the phone for this build.
  • Double tap to wake is in this build but does not work. The hidden setting meant to switch it on was discarded as the phone started up, so nothing ever armed it. The next build replaces it with a proper switch in Settings, Display.

v31debug

17 November 2026 · 1.08 GB

What changed

  • Google apps now stay through an update. You no longer need to reinstall NikGapps every time.
  • Updates can now be installed from the phone itself. The step that gets the file ready was reading a success as a failure and stopping there.
  • Choosing an update file already on the phone no longer copies only part of it.
  • Updates can be downloaded from a plain web address, not only a secure one, so a build can be served from a laptop.
  • New Recent changes button on the updates screen. It opens this page.
  • A setting to turn IPv6 off on Wi-Fi, for networks where it makes downloads very slow. Please read the note below before using it.

What was checked

  • Installed two ways on the phone, over the cable and then from the phone itself. Both finished with no errors, and the Google apps were still in place afterwards both times.
  • Photos from the back and the front camera, both full size and correct.
  • Movement and position sensors, and temperature readings.
  • The microphone still records, with the same fault at the start of a recording as before.

Worth knowing

  • The Wi-Fi IPv6 setting does not work yet. Android turns IPv6 back on as it finishes joining a network, which undoes the setting a moment after it is applied. It is being fixed properly in the next build. Until then, the setting has no effect.
  • Satellite positioning was not retested outdoors for this build. Nothing was changed that should affect it.

v30debug

16 November 2026 · 1.08 GB

What changed

  • Google apps should now survive an update. The part that saves them before the system is replaced could not write to the system partition, so it quietly saved nothing. It now writes, records each step, and says so loudly if it cannot.
  • Removed the satellite assistance setting added in the last build. It configured a path this chip does not use, so it did nothing.
  • The kernel now carries its own name, Eureka-monsiu.
  • Temperature service included and labelled properly.

What was checked

  • Temperature readings confirmed correct on the phone: thresholds now read as proper degrees rather than thousands, and the sensors report sensible values.
  • The save-and-restore fix was confirmed present in the package, but see below: it never runs.

Worth knowing

  • Google apps are still not kept across an update, and the reason is now known: the installer never runs the part that saves them. It is included in the package but never called. Being fixed in the next build. Until then, reflash NikGapps after every update, which takes about a minute and restores everything.
  • Installing from inside Android still fails before it starts, showing the robot and an error. Nothing is damaged and the phone returns to the previous build. The cause has been traced to one step that prepares the file for the installer. Installing over the cable works.
